# GPS App 需求清单

> 本文件是当前项目需求的默认执行入口。开始新需求、拆解任务或继续推进已有事项时，优先查看这里，而不是直接从 roadmap、spec 或 changelog 开始。

## 协作规则

- 优先级使用 `P0 / P1 / P2 / P3`
  - `P0`：立即处理，影响当前关键功能或当前验收
  - `P1`：近期处理，价值明确且较高
  - `P2`：中期处理，不阻塞当前阶段
  - `P3`：长期规划、预研或大项拆解入口
- 状态使用 `todo / doing / done / accepted`
  - `todo`：未开始
  - `doing`：实现中
  - `done`：代码已完成，待验收
  - `accepted`：已明确验收通过
- 同优先级下，默认优先选择 **更明确、依赖更少、已有 spec** 的条目。
- 若用户手动调整优先级，以用户调整为准。
- 代码完成后先进入 `done`，只有在有明确验收记录时才能进入 `accepted`。
- 验收未通过时，可从 `done` 回退到 `doing`。
- 复杂需求可补充 `docs/superpowers/specs/*.md` 作为详细设计；本文件只保留执行需要的信息。
- roadmap、spec、changelog 是本 backlog 的来源和历史参考，但不是当前执行状态源。
