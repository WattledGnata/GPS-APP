## 一、加速度数据离散点过滤范围调整

### 现状分析
当前代码中对加速度有效值的限制是 0-1.5G（加速）和 0-2G（刹车）。

### 实际路测数据
- 0-100 加速：7秒完成，顺势加速 G 值达到 0.9G
- 刹车测试：瞬时减速达到 1.3G

### 问题
- 加速度上限 1.5G 偏低，高性能车辆可能超过这个值
- 刹车上限 2G 偏低，紧急制动或高性能刹车可能超过这个值

### 建议方案
- 加速度范围调整为 0-2.5G（覆盖大部分家用车和性能车）
- 刹车范围调整为 0-3.0G（紧急制动可能产生更高 G 值）
- 添加配置选项，让用户可以选择"标准模式"或"高性能模式"

### 实现难度
**低**（修改阈值常量即可）

### 涉及文件
- `app/src/main/java/com/race/gps/domain/usecase/GpsDataFilter.kt`

## 三、视频拍摄 + 图层叠加

### 需求
在测试过程中录制视频，并在视频上叠加实时数据（速度、G值、时间等）。

### 技术方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | CameraX 视频录制 | 系统原生 API，稳定可靠 | 实时叠加图层较复杂 |
| B | MediaCodec + SurfaceView | 更灵活的叠加控制 | 实现复杂度高 |
| C | 先录制原始视频，后期合成 | 实现简单 | 无法实时预览 |

### 推荐方案
采用 **CameraX + OpenGL 叠加层**:
1. CameraX 负责视频预览和录制
2. OpenGL 叠加半透明的数据 HUD
3. 录制时同时合成视频和数据层

### 数据叠加内容
- 当前速度（大字体）
- 当前 G 值
- 已用时间
- 当前阶段（0-100 加速中...）
- 实时速度曲线图

### 实现难度
**高**

### 涉及文件
- 新增 `app/src/main/java/com/race/gps/video/VideoRecorder.kt`
- 新增 `app/src/main/java/com/race/gps/video/HudOverlay.kt`

## 四、完整圈速记录功能

### 需求
在地图上记录跑车的完整圈速，生成圈速报告。

### 功能拆解

#### 4.1 单向路程记录
- 起点 → 终点 的单次计时
- 例：0-400m 加速、100-200km/h 提速等

#### 4.2 完整圈速记录
- 记录连续多圈的圈速数据
- 生成圈速报告：
  - 每圈时间
  - 每圈最高速度
  - 每圈最低速度
  - 累计时间
  - 与最佳圈的差距

#### 4.3 地图可视化
- 显示赛道轮廓
- 显示当前位置
- 显示圈速分界线
- 回放圈速轨迹

### 技术方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | Google Maps SDK | 地图数据准确、API 成熟 | 需要 API key、有配额限制、国内访问受限 |
| B | 高德/百度地图 SDK | 国内数据好、无需翻墙 | 付费 API |
| C | OpenStreetMap (OSM) | 完全开源免费 | 国内地图数据可能不够详细 |
| D | 仅记录 GPS 轨迹，不使用地图 SDK | 无需第三方依赖 | 无地图底图，只有轨迹 |

### 推荐方案
采用 **方案 D（纯 GPS 轨迹）+ 可选导出功能**:
1. 记录完整 GPS 轨迹（经纬度、速度、时间）
2. 简单的 2D 轨迹视图（俯视）
3. 支持导出 GPX/KML 格式，可在 Google Earth 等工具中查看
4. 未来可扩展添加地图 SDK

### 圈速检测算法
- 方案 1: 基于地理围栏（用户在地图上标记起点/终点线）
- 方案 2: 基于速度/方向变化自动检测（检测到减速 + 转向 = 新一圈）

### 实现难度
