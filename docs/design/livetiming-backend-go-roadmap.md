## 1. 项目目标(两层)

| 层 | 目标 |
|---|---|
| **功能层** | 用我的 App 跑完赛道一圈 → 圈速实时推到一个网页,P 房的人用手机浏览器就能看到 livetiming 榜单。 |

## 2. 已锁定的决策(+ 为什么)

| 决策 | 选择 | 理由 | 拒绝的备选 |
|---|---|---|---|
| **要不要自建服务端** | 是,接云服务 | 自己电脑当服务端不行(要 24h 永远在线,睡眠/断网/关机就挂) | 本机当服务端 ❌ |
| **架构路线** | **路线 B:自写真·API + 托管部署** | 既当甲方(设计 API)又当乙方(实现+部署),完整暴露后端全流程,但砍掉最痛的机房运维 | A 纯 BaaS(Firebase 把要学的全藏起来,学不到岗位内容);C 自租 VPS 全手搓(运维太痛,起步杀鸡用牛刀) |
| **后端语言** | **Go** | ① 跟我公司/行业走(公司已从 Java Spring 迁 Go),**学了能直接用在工作上,迁移价值最高**;② 几乎无框架魔法,**最能看清后端底层概念**;③ 单静态二进制,**部署极简**;④ 并发是一等公民,正好是服务端核心 | Kotlin/Ktor(摩擦最小但迁移价值不如 Go);Node/Python(重心偏 Web/个人项目,不够"工程化");Spring(魔法多,初学易"会用不懂原理") |
| **后端放哪** | **独立新 repo** | 后端是独立可部署物、要同时喂 Android/iOS/网页、语言工具链 CI 全不同,不该塞进 Android repo | 塞进 gps-app repo ❌ |
| **v1 范围** | 只做"出圈上报圈速" | 圈速是"一圈发一次",免费档绰绰有余 | **位置上报先砍**:每秒发好几次,数据量/成本差几百倍,属重活,放 P4 可选 |

**一个有用的认知校准**(brainstorm 时聊到的):
- **语言之间**(Java↔Kotlin↔Go):基本就是语法 + 惯用法差别,底层功底同一套。Go 是"小语言",一个周末读完语法,AI 好带。**这不是难点。**
- **客户端→服务端**:**不是**"换语法写同样逻辑",而是多出一整层客户端没有的概念(并发、无状态、持久化事务、信任边界、幂等、部署运维、可观测)。**这才是要学的 80%,而且跟语言无关。**

## 3. 一条铁律(决定了能不能给 iOS 用)

> **建的是一个干净的 HTTP/WebSocket API,不是"Android 的后端"。
> Android、iOS、微信小程序观众端、P 房网页,都只是它的"客户端消费者"。**

- 只要后端是标准 API,**它天生跨平台**——iOS / 小程序那边只是换语言发同样的 HTTP 请求,后端一行都不用改。
- **推论**:别把业务逻辑塞死进某家 SDK / 平台(那样和平台耦合),要建中立 API。这也正是不走"纯 Firebase SDK"的原因之一。
- **2026-05-31 印证**:user 用过微信小程序云函数,亲身体会"微信云函数只服务小程序、自有 App 是二等公民"——要同时平等地喂 App + 小程序,**必须有自己的中立服务器**。这条铁律不是背的,是撞出来的。

## 4. 系统架构(v1 最小闭环)

```
 [Android App] / [iOS App(将来)] / [微信小程序观众端] / [P房网页观众端]
        │                                               ▲
        │  写: POST /api/sessions/{id}/laps (HTTPS)      │  读+实时: GET / WebSocket
        ▼                                               │
   ┌─────────────────────────┐        ┌──────────────────┐
   │   Go API 服务(中立)      │──写──▶│   Postgres        │
   │   谁来都发一样的 HTTP    │◀─读──│   (云数据库)       │
   └─────────────────────────┘        └──────────────────┘
        └─ 出一圈 → WebSocket 推给所有在线观众端(小程序/网页),榜单自动刷新
```

- **Go 服务**:部署在云上(**国内轻量应用服务器 / VPS**,或托管;见 §7),永远在线、公网可访问。
- **Postgres**:托管云库 或 自己在服务器上装。
- **观众端**:计划做成**微信小程序**(国内手机最自然、可微信分享扫码);开发期也可先用网页 / 由 Go 服务直接吐 HTML。
- **iOS / 小程序**(客户端):同一个 API,零后端改动——这就是 §3 铁律的回报。

## 6. 学习阶梯(P0 → P4)

> 原则:**一阶一闭环,每阶都能跑起来看到效果**,再进下一阶。不要一上来就想做全套。

### P0 · 打通最小回路(部署优先)— ⭐ 最关键的第一步
- **做什么**:一个 Go 服务,只有一个 `GET /health` 返回 `ok`。**部署到云,拿到一个公网 URL,用手机也能打开。**
- **解锁概念**:Go `net/http` 基础、**部署**、环境变量(端口从 `PORT` 读)、公网访问、HTTPS。
- **学习要点**:
  - Go 项目结构、`go mod`、`go run` / `go build`(单二进制是怎么回事)。
  - 一个 HTTP handler 长什么样(`http.HandleFunc` / `http.ListenAndServe`)。
  - 选一个托管平台(§7),把 repo 连上去自动部署。理解"我 push 代码 → 平台帮我编译 → 跑在一台永远在线的机器上 → 给我一个网址"。
- **完成标准**:手机浏览器打开那个公网 URL,看到 `ok`。**这一刻你就懂"服务端"三个字了。**

### P1 · 存一圈、读一圈(API + 数据库)
- **做什么**:`POST /api/sessions/{id}/laps` 写一条圈速进库;`GET /api/sessions/{id}/laps` 读出来。接托管 Postgres。App 端加一个"出圈后上传"的调用。
- **解锁概念**:API 设计、数据建模、SQL、持久化、JSON 序列化、请求生命周期。
- **学习要点**:
  - 设计第一版表:`sessions`、`laps`(`session_id` 外键、`lap_no`、`time_ms`、`driver`、`created_at`)。
  - Go 连 Postgres(`database/sql` + `pgx`,先不用 ORM,亲手写 SQL 最能学到东西)。
  - 路由怎么带路径参数(`/sessions/{id}/laps`),请求体 JSON 怎么解析/校验。
  - App 端:加 `INTERNET` 权限 + 一个上传函数(这块走 gps-app 的 OpenSpec 立项)。
- **完成标准**:App 跑完一圈,数据进了云库;浏览器 `GET` 能看到这条圈速的 JSON。

### P2 · 实时(让网页自动刷新)
- **做什么**:加 WebSocket(或先用更简单的 SSE),出一圈就把它推给所有打开观众网页的人。写一个巴掌大的 HTML 榜单页。
- **观众端分两步走(user 2026-05-31 拍板)**:
  - **初期 = 网页版**:Go 服务直接吐 HTML,公开链接 `http://<服务器IP>:<高端口>/`(如 `:8080`)。**免域名 / 免备案 / 免 HTTPS**(国内拦的是没备案的 80/443,高端口不拦);丑但能用、现在就能发给大家看。前提:该端口在安全组放行。
  - **后期 = 小程序版**:验证"真有人看、真有用"后再上微信小程序(域名 + ICP 备案 + HTTPS,见 §7/§8)。**先用能跑的丑版本验证价值,再花力气美化。**
- **解锁概念**:实时推送、长连接、发布/订阅、客户端订阅。
- **学习要点**:
  - WebSocket 服务端怎么维护"在线的观众连接列表",新圈来了怎么广播。
  - 先做最朴素版本(内存里存连接);理解为什么"多实例部署"时这会变复杂(为 P3/扩展埋个概念点)。
  - 网页端:`new WebSocket(...)` 监听 → 收到新圈 → 刷新榜单 DOM。
- **完成标准**:两个手机各开一次网页,App 出一圈,两个网页**同时**蹦出新圈。

### P3 · 安全(信任边界)
- **做什么**:加 token 鉴权(只有我的 App 能写)、上传校验、限流、防伪造圈速。
- **解锁概念**:认证、授权、信任边界("客户端传来的一切都假设是伪造的")、限流、幂等(同一条圈速重发不能算两圈)。
- **学习要点**:
  - 写接口加一个 `Authorization` token 校验中间件。
  - 读(观众看榜)开放,写(上传圈速)要鉴权。
  - 幂等:上传带一个客户端生成的 `lap_uuid`,服务端去重。
- **完成标准**:不带 token 的写请求被拒;重复上传同一圈不会出现两条。

### P4 · 可选扩展(以后想深入再说)
- **iOS 端接同一 API**:验证"铁律"——后端零改动,iOS 只是换语言发同样请求。
- **位置上报(重活)**:高频(每秒数次)位置流 + 地图。数据量/成本上一个量级,要重新评估免费档够不够、要不要降频/分层。**确定要做时单独立项。**
- **运维深化**:结构化日志、指标面板、报警;多实例部署时的实时广播(引入 Redis pub/sub 之类)。

## 7. 技术选型清单(开建时再终定,免费档条款常变,以官网为准)

| 模块 | 首选 | 备选 | 说明 / 成本 |
|---|---|---|---|
| **后端语言** | Go(标准库 `net/http` 起步) | 加路由库 `chi`(轻、不魔法) | std-lib 优先,**先别上框架**,最能看清概念 |
| **部署(计算)** | **国内轻量应用服务器**(阿里/腾讯 Lighthouse) | 境外 PaaS(Railway/Render/Fly/Cloud Run);域内云托管/SAE/函数计算 | 详见下方「国内云选型」。**境外 PaaS 国内访问/支付不便、观众延迟差**;函数计算对 WebSocket 别扭 |
| **数据库** | 托管 Postgres:RDS(国内)/ Neon / Supabase | **自己在服务器上装 Postgres**(更省+更学到东西) | Go 用 `pgx` 直连,先不用 ORM |
| **实时** | WebSocket(`coder/websocket` 或 `gorilla/websocket`) | 先用 SSE(更简单) | P2 再引入 |
| **观众端** | **微信小程序**(计划) | 调试用网页 / Go 直接吐 HTML | 国内手机最自然、可微信分享扫码;硬约束见下方 + §8 |
| **域名 + HTTPS + 备案** | **迟早必须**(被小程序观众端逼出来) | —— | 学习/本地阶段不需要;发布小程序观众端时:HTTPS + 域名进小程序「合法域名」白名单 + 国内服务器 ICP 备案 + HTTPS 证书(有免费的) |

**总成本预期**:**学习阶段(本地/局域网)¥0**;真发布小程序观众端 = 轻量服务器(约 ¥100-200/年)+ 域名(约 ¥70/年)+ 备案(免费,要 1-2 周)。

### 国内云选型(2026-05-31 补,user 正在调研)

国内云**不止卖裸服务器**,分两类(对应路线 C / B),逛控制台会同时看到:

| 类型 | 阿里 / 腾讯叫法 | 大白话 | 适合谁 |
|---|---|---|---|
| 裸 VM(路线C) | **轻量应用服务器 / Lighthouse** | 简化版裸服务器,固定价、控制台傻瓜、自带公网 IP | ✅ **新手 VM 首选**;自己做运维 = 学得透 |
| 裸 VM(路线C) | ECS / CVM | 完整云服务器,更灵活但更繁 | 暂不需要,轻量够 |
| 托管(路线B) | 云托管 CloudBase / SAE / Web+ | 给程序它帮你永远在线跑,不管 VM | 想少运维可选,但藏了你要学的运维 |
| Serverless(路线B) | 函数计算 FC / 云函数 SCF | 只传函数、按需跑、缩到 0 | 简单 API 行,**WebSocket 实时别扭** |

**逛控制台只盯三样**:计算(选轻量)+ 数据库(RDS 或自己装)+ 安全组(开端口)。其余 OSS/SLB/CDN/VPC 先无视。

**小程序观众端的硬约束**(发布时):`wx.request` 必须 ① HTTPS ② 域名进小程序后台「合法域名」白名单 ③ 国内服务器 ICP 备案;**不能裸 IP / 不能 HTTP**。开发期开发者工具可勾「不校验合法域名」连本地/IP 调试。
