## Context

当前视频 HUD 的数据同步已经稳定：回放和导出都以 frame wall-clock 解析速度、圈时、delta、G 值与小地图位置；图元绘制部分也已下沉到 `OverlayCanvasPainter`。但布局仍分散在 Compose 四角组件和导出端坐标代码中，新增多套样式若继续双端分别排版，会重新引入“预览与成片漂移”。

本变更跨越 Compose 回放、轻量偏好持久化、前台导出 Service 和 GL overlay Bitmap，因此需要一个样式模型与单一共享 HUD 绘制入口。

## Goals / Non-Goals

**Goals:**

- 提供 `FLAT`、`RAIL`、`MECHANICAL` 三种稳定样式，默认 `FLAT`。
- 用户切换后回放即时更新，选择跨页面和进程重启保留。
- 全屏回放、内嵌回放、单段导出、跨段导出使用同一套布局与绘制逻辑。
- 导出任务启动时冻结样式，导出过程中再次切换不改变正在编码的成片。
- 保持现有遥测同步、视频裁剪、音轨直通和失败清理语义。

**Non-Goals:**

- 不提供自由拖拽、任意缩放、颜色编辑或单图层开关。
- 不保留旧四角 HUD 为第四种用户可选样式。
- 不修改视频编码器、BLE/GPS、Room、binary 或 Livetiming 协议。
- 不引入第三方绘图、地图库或视频库。

## Decisions

### 1. 使用稳定枚举作为跨层样式契约

新增 `VideoOverlayStyle { FLAT, RAIL, MECHANICAL }`，持久化与 Intent 传输均使用枚举名。解析未知/空字符串时返回 `FLAT`。

选择枚举而非整数：枚举名在版本演进中可读、可测试，不受排序调整影响。选择单一枚举而非一组自由参数：三套视觉可以作为整体进行质量控制，避免组合爆炸。

### 2. Preferences DataStore 只保存全局“上次选择”

新增轻量 `VideoOverlayStylePreferences`，提供 `Flow` 与挂起写入方法。视频 HUD 样式不是 session 业务数据，不写 Room，也不修改历史 session。

`FLAT` 是无值、损坏值和未来未知值的统一降级。选择全局记忆而非每 session 保存，是因为用户表达的是导出风格偏好，而不是圈速记录本身的属性。

### 3. 回放与导出共享整帧 Canvas HUD 渲染器

在 `OverlayCanvasPainter` 上新增整帧入口，输入画布尺寸、`VideoOverlayStyle` 和统一 `OverlayHudFrame`，由同一函数完成布局和图元绘制：

- Compose 回放通过一个透明 `Canvas` 调用该入口。
- 导出通过透明 Bitmap 的 `Canvas` 调用同一入口。

旧的速度表/G 球/小地图基础图元函数继续复用，但三套布局不再由 Compose 和导出各写一份。相比继续组合多个 Composable，这能直接保证像素布局一致，也降低跨分辨率适配成本。

### 4. 使用归一化比例和安全边距计算布局

布局按画布短边计算字号、线宽与内边距，并以画布宽高比例确定区域：

- `FLAT`：大号无框速度与圈时分布在左右安全区，G 值与地图弱化。
- `RAIL`：底部单条半透明栏，五类信息对齐到同一基线。
- `MECHANICAL`：左下合并仪表簇 + 右下地图，整体高度不超过画面 25%。

内嵌小面板通过相同归一化布局自然缩放，不再用 Compose 组件整体 `scale=0.5f` 复制布局。

### 5. 选择器是回放控制，不烧进视频

全屏回放顶部提供“HUD 样式”入口，打开三张样式卡；点击即写入偏好并更新画面。选择器、播放按钮、Slider 和导出进度属于控制层，MUST NOT 进入共享 overlay Canvas，因此不会烧录到成片。

内嵌回放只展示当前全局样式，避免小面板塞入额外控件。用户从全屏页切换后，内嵌页随偏好流更新。

### 6. 导出启动时通过 Intent 冻结样式

`VideoExportService.start` 读取当前偏好并写入 `EXTRA_OVERLAY_STYLE`；Service 解析后把样式传入单段/跨段 pipeline 与 `ExportOverlayRenderer`。缺少或非法 extra 时使用 `FLAT`。

相比在编码每帧读取 DataStore，冻结快照可避免长导出过程中样式突变，也消除每帧 IO。

## Risks / Trade-offs

- [Canvas 文字排版与 Compose 字体度量不同] → 回放也改走同一个 Canvas 入口，以最终成片的真实绘制为准。
- [机械样式在低分辨率视频上过密] → 所有尺寸按短边缩放，并锁定最小字号与 25% 高度上限。
- [明亮视频上 `FLAT` 对比不足] → 在文字局部使用渐变/半透明 scrim，而不是给每个元素加独立卡片。
- [修改共享绘制层可能影响现有导出] → 保留基础图元纯函数测试，新增三样式布局几何和导出样式透传测试。
- [用户在导出中切换样式产生认知差异] → 导出开始时冻结样式，并在导出入口显示本次使用的样式名。

## Migration Plan

1. 先加入枚举、偏好仓库和解析测试，默认值保持 `FLAT`。
2. 加入共享整帧 HUD 入口与三套布局测试。
3. 将全屏/内嵌回放切换到共享入口，再接选择器。
4. 将单段/跨段导出接入冻结的样式参数。
5. 真机对三种样式分别截图，并各导出一段短视频核对预览/成片。

回滚时可恢复旧 `OverlayHud` 组合与 `ExportOverlayRenderer` 调用；新增 DataStore 键留存不会影响旧版本运行。
