## Why

视频分段已经能在全屏页连续回放，但圈详情小窗、覆盖判断和导出仍残留单文件模型：
跨段圈可能出现小窗与全屏行为不一致、段间黑屏停顿、导出被直接拒绝或错误显示“视频不完整”。
同时，播放、导出和删除入口分散在页面不同位置，删除整场录像的危险操作过于醒目且语义不够明确。

## Scope

本次变更：

- 建立统一的圈视频时间轴计划，以多个 `VideoSegment` 的覆盖区间并集作为播放、导出和 UI 状态的共同事实源。
- 圈详情小窗与全屏页都按分段列表回放；明确展示分段边界和缺失画面，避免无反馈的黑屏等待。
- 支持跨段圈导出：只处理目标圈窗口涉及的局部片段，按时间轴拼接并继续烧录现有遥测 overlay。
- 重做播放控制区和导出状态：提供明确的播放/暂停、分段时间轴、导出进度、取消、失败重试及完成后的查看/分享操作。
- 将“删除本场视频”迁入 Session 顶部更多菜单，改为“删除本场全部录像”，展示分段数和可释放空间，并明确保留圈速与遥测数据。
- 视频存在性、覆盖状态和删除范围统一读取 `video_segments`；旧 `TelemetrySession.videoFilePath` 只保留兼容 fallback。

本次不修改录制分段策略、RaceChrono BLE 协议、GPS 判圈逻辑，也不新增云端视频上传。

## Acceptance

- 同一跨段圈在详情小窗和全屏页都能从圈前导时间连续播放到圈后导时间，拖动后画面、overlay 和时间轴保持同步。
- 分段切换不出现无限等待；真实缺失画面有明确可识别状态，短切段间隙不会造成明显停顿。
- 覆盖多个分段但圈本体完整的圈允许导出；导出结果可播放、时长合理、段边界前后画面和 overlay 连续。
- 部分缺失的圈不会被误报为“无视频”；UI 能区分完整、部分和无覆盖，并给出可理解的导出提示。
- 导出过程可取消；成功后不强制弹分享页，用户可选择查看、分享或关闭；失败后可看到原因并重试。
- Session 主内容流不再展示通栏红色删除按钮；菜单确认框显示全部分段数量/空间，删除后所有录像文件与分段行移除，但圈速、crossing、binary 和 session 保留。
- 定向单元测试和当前工程实际提供的 `:app:assembleDebug` 通过，并生成可安装 APK 供真机路测。

## Impact

- `feature/test/src/main/java/com/blazepush/feature/test/export/`：统一时间轴/覆盖计划和跨段导出管线。
- `feature/test/src/main/java/com/blazepush/feature/test/ui/tracktech/`：详情小窗、全屏播放、导出反馈及 Session 菜单。
- `core/data/src/main/java/com/blazepush/core/data/`：复用分段查询并补充录像统计/删除结果所需的数据接口；原则上不新增 Room migration。
- `feature/test/src/test/`、`core/data/src/test/`：时间轴、覆盖、跨段裁剪计划和删除语义回归测试。
- 协议兼容性：不修改 BLE、服务端或既有录像文件格式；旧 session 单路径数据继续通过兼容 fallback 播放和删除。
